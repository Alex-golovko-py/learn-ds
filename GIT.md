## Зачем это нужно

Git хранит историю изменений проекта. Каждый коммит — снимок состояния, к которому можно вернуться. Это страховка («я всё сломал») и дневник работы одновременно. GitHub — копия этой истории в облаке: второй экземпляр на случай проблем с диском и витрина работ для будущего работодателя.

---

## Ежедневный ритм

Три команды после каждого занятия:

```powershell
git add .
git commit -m "Блок 1, урок 3: словари"
git push
```

`add .` — отобрать все изменения для сохранения.
`commit -m "..."` — записать снимок с описанием.
`push` — отправить на GitHub.

Коммитить лучше **после каждой завершённой темы**, а не раз в неделю. Мелкие частые коммиты полезнее редких огромных: по ним видно, что менялось, и откатываться проще.

---

## Как писать сообщения коммитов

Хорошее сообщение отвечает на вопрос «что изменилось».

Плохо: `update`, `фикс`, `1`, `работа`
Хорошо: `Блок 1, урок 5: циклы for`, `Исправил ошибку в подсчёте среднего`, `Добавил датасет по продажам`

Формат для учёбы: `Блок N, урок M: тема`.

## Что происходит и где я

```powershell
git status
```
Что изменено, что готово к коммиту, на какой ветке. Самая частая команда — запускать при любых сомнениях.

```powershell
git log --oneline
```
История коммитов коротким списком. Выход — клавиша `q`.

```powershell
git diff
```
Что именно изменилось в файлах с последнего коммита. Выход — `q`.

## Типовые ситуации

### Сломал файл, хочу вернуть как было

Файл изменён, но ещё не закоммичен:

```powershell
git restore имя_файла.ipynb
```

Вернёт файл к состоянию последнего коммита. Несохранённые правки пропадут — в этом и смысл.

### Отменить последний коммит, но оставить изменения

```powershell
git reset --soft HEAD~1
```

Коммит исчезнет, файлы останутся изменёнными. Полезно, если поторопился или ошибся в сообщении.

### Ошибся в тексте сообщения

```powershell
git commit --amend -m "Новый текст"
```

Только если коммит ещё не отправлен на GitHub.

### Случайно добавил лишний файл в `git add`

```powershell
git restore --staged имя_файла
```

Уберёт из подготовки, сам файл не тронет.

### Посмотреть, как выглядел файл раньше

```powershell
git log --oneline имя_файла
git show <хеш_коммита>:путь/к/файлу
```

Хеш — короткий код вида `a3f21b8` из вывода `log`.

## Работа на другом компьютере

Склонировать проект:

```powershell
git clone https://github.com/Alex-golovko-py/learn-ds.git
cd learn-ds
uv sync
```

`uv sync` восстановит окружение из `pyproject.toml` — поэтому `.venv` и не хранится в git.

Забрать изменения, сделанные в другом месте:

```powershell
git pull
```

## Что НЕ попадает в git

Всё перечисленное в `.gitignore`:

- `.venv/` — окружение, восстанавливается через `uv sync`
- `.ipynb_checkpoints/` — служебный мусор Jupyter
- `data/*.csv` и другие данные — датасеты бывают большими, git для них не предназначен
- `.env`, ключи — секреты в репозиторий не кладут **никогда**, даже в приватный

Если нужно закоммитить файл вопреки `.gitignore`:

```powershell
git add -f имя_файла
```

## Ветки (пригодятся позже)

Пока вся работа идёт в `main`, и этого достаточно. Ветки понадобятся в блоке 2+ и при проектах.

```powershell
git switch -c имя_ветки     # создать ветку и перейти в неё
git switch main             # вернуться в main
git merge имя_ветки         # влить ветку в текущую
git branch                  # список веток
```

Смысл: экспериментируешь в отдельной ветке, `main` остаётся рабочим. Получилось — влил, не получилось — удалил ветку.

## Настройки (делаются один раз)

```powershell
git config --global user.name "Имя"
git config --global user.email "почта"
git config --global core.quotepath false   # чтобы кириллица в именах файлов не превращалась в коды
```

## Правила, которые экономят нервы

1. `git status` перед любым непонятным действием.
2. Коммит после каждой завершённой темы, а не «когда-нибудь потом».
3. Секреты и пароли в репозиторий не попадают никогда.
4. Не паникуй: почти всё в git обратимо, если коммит был сделан. Именно поэтому коммиты частые.
5. Не уверен в команде — спроси, прежде чем выполнять. Особенно если в ней есть `reset --hard`, `clean -f` или `push --force`.
